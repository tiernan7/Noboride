# Analysis methods and limits

## Comparison contexts (dev)

The source editor and accepted analysis entries are separate. Tabs browse included recordings; the first accepted stretch stores the comparison's road definition and owner entry. Removing that owner clears its road-specific decisions. A sole surviving nonrejected stretch becomes the road; multiple survivors wait for an explicit road choice or the next added stretch. Both deletion/addition orders and failed-save rollback are supported. Automatic suggestions use the existing GPS verifier on that definition, including repeated passes of its own source recording. Suggestions require explicit acceptance. Fractional endpoint indices are persisted and reconstructed using the same sample interpolation, preserving elapsed timing and missing channels. Accepted automatic entries are reverified under current matching settings and marked unavailable if verification no longer succeeds; they are not silently replaced by another pass.

Manual additions and adjustments may represent different roads, so their entries are labeled manually paired efforts. Time/sensor charts remain aligned by normalized distance progress. Terrain attribution is hidden whenever the currently analysed entries include a manual effort; unrelated efforts must not acquire geographic time-savings claims. The baseline is an entry ID, independent of the editor tab, and several entries may reference one source ride. Contexts persist settings, baseline, metric and source browsing state; saved road definitions remain separate. Broad discovery of previously unselected shared subsections is not implemented.

Ride inclusion controls the analysis as well as the browser. Accepted entries remain persisted, but only entries belonging to checked rides and passing any required GPS reverification enter statistics, charts, CSV and whole-ride context. Excluded entries appear in a collapsed saved-stretch list with explicit inclusion actions. The active comparison reports actual available/total counts; dropdown availability is based on the current checked set, with a Review matches state for an active comparison whose selected entries cannot all be verified. Switching contexts preserves that checked set rather than silently restoring a different one. Reload restores the last active snapshot's selection. Track loading on activation requests selected recordings and the original road reference, not every excluded entry. The original reference can still be loaded internally for GPS verification and the shared terrain profile; it does not contribute an unchecked analysis row.

Unchecking or failing to reverify a saved baseline does not substitute or overwrite its ID. Raw statistics remain available for the selected stretches; baseline-relative deltas, overlays and terrain comparisons pause with an explanation until its ride is included, its verification succeeds, or the user explicitly chooses another available baseline. Selection changes preserve entry IDs, endpoints and repeated-pass identities, including in backups. Removing an entry is still a separate destructive action.

Each context also stores integer-indexed browsing ranges per source ride. These are editor drafts, independent of accepted entries and their potentially fractional matched endpoints. Viewing or brushing a range does not alter accepted entries; updates are explicit. The source map and numbered profile rows show every accepted range for the active ride, including entries currently unavailable for automatic analysis. Overlapping GPS paths can coincide on the map; separate profile rows distinguish recording positions and repeated laps. Legacy section definitions are retained in backups but no longer have separate save/switch controls in this editor.

Suggestion de-duplication compares overlapping ranges on the same recording using shared distance divided by combined distance (intersection over union), interpolated from the source's cumulative distance. For example, a 0.38 mi suggested range and a 0.32 mi accepted range sharing 0.27 mi have a combined span of 0.43 mi, giving approximately 63% overlap. **Settings → Hide overlapping suggestions** adjusts the required percentage from 10–100%, default 60%. Lower percentages hide more suggestions; 100% requires identical ranges. The setting is validated and saved with the comparison, including backups; older workspaces receive the default. Chronologically separate passes have no overlap even when their GPS paths coincide. This replaces the former fixed overlap and endpoint-distance tolerances. It only hides redundant suggestions; it does not change saved endpoints, accept suggestions automatically, or verify manually edited entries as GPS matches. Removing the accepted stretch lets its original suggestion reappear.

## Ride story and nested terrain (dev)

The linked source view, terrain hierarchy and correctable road review are documented in [RIDE-STORY.md](RIDE-STORY.md). Terrain detection is independent of effort channels and does not infer intent. Boundary corrections attach to comparison-local section IDs and stable source sample positions without rewriting tracks. Source-story axes are distance or elapsed recording time and retain surrounding data. Route inspection uses original coordinates; human confirmations, automatic GPS verification and similar-terrain pairings remain distinct. Manual same-road corrections still suppress geographic terrain attribution. Rejections and their reasons persist per comparison and can be reversed.

The linked view is now integrated into the single Ride browser: one map, one set of source traces and shared boundaries serve terrain editing and comparison stretches. Brushing uses the displayed distance/time axis and selects original integer sample indices. Comparison rows retain their fractional saved endpoints until explicitly updated. Choosing included terrain or an accepted stretch opens the same linked comparison section. Add creates its definition and included range together; Save changes updates both atomically within the active comparison. The presentation changes do not modify matching, statistics or source samples.

## Import normalization

FIT decoding uses Garmin's official JavaScript SDK, with scale/offset, subfields/components, date conversion and heart-rate merging enabled. Semicircle positions are converted to degrees. Enhanced altitude/speed take precedence; array-valued fields are handled. Timer events mark pauses when present. The file's integrity check must pass.

TCX activity/lap/track records preserve recorded distance and supported sensor extensions; device lap timer values are summed. Empty or untimed GPX/TCX sibling tracks/activities are skipped without discarding later usable tracks. GPX requires timestamps, preserves explicit track-segment breaks and supports Garmin TrackPointExtension HR/cadence/temperature. XML external entities/DOCTYPE are rejected.

Points are sorted by timestamp; duplicate timestamps are removed. Implausible sensor values are made missing, not clipped to plausible-looking numbers. Cumulative-distance resets are offset and warned about. When distance is absent, continuous GPS legs supply haversine distance, falling back to recorded speed. No GPS chord is added over explicit breaks or time gaps over 30 seconds. Summary metadata and normalized tracks are kept separately; tracks are gzip-compressed inside SQLite. IDs are hashes of input content plus session/track index, enabling repeat-import deduplication. A FIT and TCX export of the same activity may still produce separate IDs; include only the representation you want.

## GPS gates and passes

Each reference endpoint is projected onto every continuous GPS leg of another ride, using a local tangent-plane projection and clamping to each leg. Adjacent hits within the gate radius are clustered; the nearest projection in each visit supplies an interpolated sample and timestamp. This keeps repeated visits to a gate on different laps separate.

Candidate start/end visits must be chronological and between 0.65 and 1.5 times the reference section's recorded distance. Thirty-three ordered probes compare candidate and reference geometry at equal distance progress. The largest offset must be below max(65 m, 2.5 × gate radius). This rejects opposite-direction passes, substantial detours and routes with only endpoints in common. It is deliberately conservative, not a full road-network map matcher. Automatic matching does not bridge explicit breaks or recording gaps over 30 seconds. A brief interior loss of GPS is bridged only for geometry verification when bounding GPS observations are at most 30 seconds apart. Original missing coordinates and other source samples remain missing. The maximum bridge duration is exposed in the GPS-offset cell and CSV. That fixed matching continuity limit is separate from the configurable statistical gap threshold.

Endpoints are interpolated within samples. The table exposes both gate miss distances and the maximum ordered-route offset (hover the GPS-offset cell). The map shows the active source editor's selection; preview an automatic suggestion to inspect its source range. Source-marker dragging and coordinate snapping select recorded source samples. If the road is revisited on several laps, use chart/sliders to disambiguate.

Legacy saved road definitions can retain one manual override per ride, as in earlier backups. The dev comparison workspace instead stores independent manual entries; adding or adjusting one does not replace another entry from the same ride. Such entries bypass automatic route verification, are labeled manually paired efforts, and are saved in their comparison context.

## Timing, sensors and missing data

The [Hills library](HILLS.md) records explicit physical identities and per-pass hill-only boundaries/review metadata independently of comparison sections. Its display profile geographically projects vetted members onto an extensible recorded spine, estimates only constant altitude offsets over overlaps, averages repeated passes within each ride and gives rides equal weight. Position support varies; the band shows a range, not a confidence interval. Its display mapper does not replace or relax conservative timing verification. One terrain-explorer point represents one named identity; multiple-hill aggregate profiles stay within Hills. See HILLS.md for exact mapping thresholds and limitations.

Existing independent terrain comparisons retain raw traces and a raw **Δ elapsed** against the explicitly selected baseline, while disabling geographic time-delta overlays and common-road terrain attribution. Different lengths/boundaries affect duration differences. Raw accumulated ascent stops after unknown elevation or a recording discontinuity; it is noise sensitive.

Elapsed time is end timestamp minus start timestamp. Timer time is the integration of FIT timer events when available. Whole-ride source timer/moving metadata are displayed separately. Moving estimate integrates intervals whose distance/time exceeds the selected threshold and whose starting timer state is not paused. Recording gaps are excluded from moving estimates.

HR, cadence and recorded power use trapezoidal time weighting over intervals where both endpoints have data, excluding gaps and explicit breaks. This avoids weighting dense sampling more than sparse sampling. Missing sensor values are never zero-filled. Zero cadence or watts, if recorded, are valid.

## Grade and altitude

For each sample, an adjustable physical-distance window is centered on its cumulative distance and clipped to the section's boundaries. Elevation is interpolated at the window endpoints; grade = 100 × elevation change / distance change. Windows crossing missing elevation, explicit breaks or recording gaps return missing grade. Short edge windows below max(5 m, one quarter of the chosen window) are omitted. This is a defined smoothing method rather than Garmin's proprietary grade calculation.

The display uses the 3/6/9/12% color thresholds. Negative and gentle grades share the lightest color on the elevation profile; use the grade comparison chart for signed slope. A steep-looking edge in a graph can be an elevation-data artifact. The method cannot recover terrain detail absent from the file.

Relative elevation overlays subtract each pass's initial altitude; they do not force its endpoint elevations to match. Estimated ascent/descent use a 3 m deadband to reduce tiny noisy reversals and are not an official Garmin total.

## Terrain time attribution

All passes use the chosen reference's grade profile, with climbs above +threshold and descents below -threshold; the rest is level. The default threshold is ±1%. Each observed moving interval is subdivided into spans no longer than 10 m. At each midpoint, its normalized distance progress is mapped onto the reference profile, and that fraction of elapsed interval time goes to the corresponding terrain class. Slow/known-paused intervals, recording gaps and unknown-grade intervals have separate buckets. Bucket totals equal elapsed time, apart from floating-point rounding.

This produces an approximate answer to “how much of the time gain came downhill?” without relabeling a road because another recording had a shifted altitude. It is not exact geographic alignment at every interior point: differing wheel/GPS distance accumulation or a manual pass on another road can distort allocation. Inspect route overlays and endpoints. Saved overlapping sections are never silently added together into a whole-ride total.

Cumulative delta curves and sensor overlays use the same distance-progress convention. The final delta equals elapsed-time difference. Intermediate values are interpolated observations, not independent measurements. No significance tests, model-derived power or inferred physiological thresholds are presented.

## Public recording and noise regression coverage

`tests/fixtures/cerknicko-jezero.gpx` is a public timed track from gpxpy, pinned to a repository commit with a SHA-256 checksum in `source.json`. The upstream license is alongside it. Its first empty track exposed an import bug now fixed. The unchanged recording's longest continuous 55-sample section matches at its original 446-second duration (about 645.22 m).

Additional tests resample the public GPS polyline to 5 m intervals, assign controlled synthetic timestamps and sensors, and then perturb the observations. This is real recorded track geometry with simulated sampling/performance, not a new real-world ride or a surveyed road centerline. Straight interpolation between sparse source points cannot recover the road's missing curves. The original recording's sport/provenance is not independently verified.

Thirty fixed seeds use independent Gaussian jitter (2 m standard deviation per coordinate axis), temporally correlated drift (6 m marginal standard deviation, AR(1) coefficient 0.96), 1–7-step variable sampling, altitude offset/noise and a known 1.08 speed factor. In the current run all 30 matched and maximum endpoint-duration error was 3.39 s against a 12 s test tolerance. Ten additional independent noisy-reference/noisy-candidate pairs matched. These finite simulations are regression coverage, not a statistical accuracy guarantee for a particular receiver.

Other cases cover GPS-derived distance, repeated noisy passes, short GPS dropout, long GPS-only/recording outages, sustained 180 m displacement, alternate paths, and stationary recorded distance despite GPS jitter. Large or discontinuous errors are deliberately rejected for manual review rather than automatically accepted.
